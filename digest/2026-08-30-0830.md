## The Headline
**Tencent drops Hy4 Preview** — 770B MoE (49B active), 1M context, open-source, and the model itself participated in optimizing its own training pipeline and inference system. That recursive self-improvement loop is the real story, not the benchmark scores.

## The Stack

[Frontier Models] **Tencent Hy4 Preview** — 770B MoE with 49B active params and 1M+ context. Open-sourced, available on OpenRouter and Tencent Cloud. The kicker: it ran experiments on its own training methods, data strategies, and low-level operators, producing a recursive self-improvement loop that fed results back into development. Also autonomously optimized its inference infrastructure for a 31.8% throughput gain. API: $0.834/M input, $2.501/M output. <https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/>

[Hardware] **Samsung Processing-in-Memory (PIM)** — LPDDR5X chips with MAC units baked into each DRAM bank. Internal bandwidth hits 614 GB/s across 16 banks vs 76.8 GB/s external. Theoretical INT8 throughput: 2.4 TOPS per chip. The clever bit is it uses standard LPDDR5X protocol with special row addresses as control registers. The ugly bit: PIM memory must be uncacheable, breaks CPU prefetching and OoO execution, and multitasking is a nightmare. Great silicon, but the software story is still a horror movie. <https://chipsandcheese.com/p/hot-chips-2026-samsungs-processing>

[Hardware] **vLLM v0.28.0** — 584 commits from 270 contributors. Kimi-K3 got dedicated decode kernels, DCP support, and adaptive speculative token budgets. DeepSeek V4 now has end-to-end sparse MLA working with MTP and DSpark. Tiered KV cache offloading to disk, Rust frontend with gRPC, and Model Runner V2 nearing maturity. The E/P/D disaggregation and weight offloading are landing just as everyone starts asking "how do I run this monster on my hardware?" <https://github.com/vllm-project/vllm/releases/tag/v0.28.0>

[Agents] **Domain-Driven Agents** — A concrete methodology for making brownfield codebases legible to AI agents using DDD. Every repo gets a `.workflow.json` manifest declaring bounded contexts, glossaries, and context-map edges. The trick: edge declarations are cross-checked mechanically — disagreement becomes an auto-filed issue on the wrong side. Strategic work (deciding what to change) stays human; tactical work (implementing it) goes to agent skills and sub-agents. This is the first systematic approach I've seen to the "LLMs fail on legacy code" problem that isn't hand-waving. <https://coldtake.dev/blog/domain-driven-agents>

[Breakout] **StemDeck** — Free, open-source, local AI stem separator using Meta's Demucs htdemucs_6s. Splits any audio into 6 stems (vocals, drums, bass, guitar, piano, other) entirely on-device. DAW-style mixer with waveforms, BPM/key analysis, export individual stems or custom mix. Built on FastAPI + Tauri v2. 199 points and 18.7k GitHub stars for a reason — it does one thing well with zero friction. <https://github.com/stemdeckapp/stemdeck>
