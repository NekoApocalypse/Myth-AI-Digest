# 🐱 Daily AI Digest — 2026-07-26

## The Headline
**A 28.9M param LLM running at 9.5 tok/s on an $8 ESP32 microcontroller.** Not a cloud API, not a Raspberry Pi — a literal microcontroller with 512KB SRAM. The trick is Google's Per-Layer Embeddings (from Gemma 3n/4): 25M of those params sit in cheap flash memory, and only ~450 bytes get pulled per token. Previous record on this class of chip was 260K params — that's a 100x jump. This isn't a better benchmark score; it's a legit on-device inference breakthrough.

## The Stack

- [**Hardware**] **LLM on $8 ESP32-S3** — <https://github.com/slvDev/esp32-ai> (49 pts) — 28.9M params, 4-bit quantized to 14.9MB, entirely on-device with no connectivity. Trained on TinyStories so it writes coherent micro-fiction, not code. The architecture matters more than the output: proves you can decouple the embedding table from SRAM and run real-scale language models on silicon that costs less than a coffee. Code, firmware, wiring docs, and full ablation results all in the repo.

- [**Agents**] **Yorishiro — a terminal your AI inhabits** — <https://github.com/sktkkoo/Yorishiro> (34 pts) — macOS terminal app that gives Claude Code or Codex a VRM character with real-time expression, gaze tracking, and MCP-powered environment control. The interesting bit: everything is "packs" — modular JS files for persona, scene, UI, effects — and the agent can rewrite its own packs through conversation. User and agent share the same environment symmetrically. More "presence harness" than capability booster, but the structural MCP pathways (body/space reachable, user files not) is a clean safety model.

- [**Architecture / Hardware**] **PyTorch Monarch lands on AMD GPUs** — <https://pytorch.org/blog/bringing-pytorch-monarch-to-amd-gpus-single-controller-distributed-training-on-rocm/> (60 pts) — Single-controller fault-tolerant distributed training ported from CUDA to ROCm via hipify_torch. The big deal: dynamic node recovery without full checkpoint restarts. When a GPU node dies, Monarch's supervision tree isolates the failure, peer-transfers state from a healthy replica, and resumes — all while other replicas keep training. Validated on 128-GPU SLURM and 256-GPU Kubernetes clusters (MI300/MI355). 1,171 tests passing on ROCm 7.0+. AMD's training story is getting real.

- [**Frontier Models**] **The new rules of context engineering for Claude 5 generation models** — <https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models> (131 pts) — Anthropic's official guidance on context management for Claude 5-class models. Content gated behind JS-heavy rendering (article body unavailable), but the title and 131-point traction suggest a meaningful shift in how context windows behave at the next generation. Worth revisiting when mirror/archive surfaces.

- [**Breakout**] **Open-weight AI is having its Kubernetes moment** — <https://tobi.knaup.me/2026-07-25-open-weight-ai-is-having-its-kubernetes-moment/> (298 pts, 242 comments) — #1 story by engagement. 403 on fetch, but the 298-point signal is loud: the open-weight ecosystem is hitting the same standardization/commoditization inflection that Kubernetes brought to container orchestration. The HN thread alone is probably the real content here.
