# 🗞️ Daily AI Digest — 2026-11-24

## The Headline

**GLM-5.4 ships the first production-scale Loop Transformer.** Z.ai looped 28 layers of their GLM-5 base model to run twice per forward pass, hitting performance comparable to 2T-3T parameter models without adding parameters. This is the first time recurrent depth has been validated at the 750B scale — prior looped models always lagged unshared architectures under the same compute budget. The key trick: they adapted an already-pretrained base model via continued training with gated progressive updates, hybrid KV caching, and sparse attention index reuse. Not open weights yet.

## The Stack

**[Architecture] GLM-5.4 — Loop Transformer at 750B Scale**  
28 weight-shared layers run two iterations per token. Gated progressive updates let the first pass build global context conservatively while the second pass refines output, with gates adapting step size per token difficulty. The architecture side-steps the traditional compute-depth tradeoff: you get ~36% more effective depth with zero parameter increase. Sparse attention indices are computed once and reused, and the KV cache only costs one sliding window extra per loop. If this architecture pattern holds, it changes how we think about scaling laws.

**[Hardware] NariQ: 27B Model at BF16 Quality in 10GB**  
Nari Labs released a trellis-coded post-training quantization of Qwen3.8-27B. At 3-bit (10.1 GB), it matches BF16 on long-horizon agent tasks (DeepSWE, Terminal-Bench), math (AIME), and vision benchmarks. The calibration was done on real coding-agent traces, not generic text — which is probably why it holds up on agent tasks better than previous quantization schemes. Requires a custom llama.cpp fork; upstream merge is pending.

**[Agents] Greptile: Screenshots vs Accessibility Trees for Computer Use**  
Systematic evals across 7 OpenAI models on OSWorld. Key result: GPT-6.1 Sol scores 83.8% with screenshots alone and doesn't meaningfully improve with accessibility trees or ID-based clicking. But GPT-5.2 goes from 15.8% (screenshots alone) → 36.2% (+tree) → 52.8% (+ID clicks). If you're building on weaker/cheaper models, the tree still pays for itself. Their TREX agent uses screenshots as primary and falls back to tree-based ID clicks when elements are available.
